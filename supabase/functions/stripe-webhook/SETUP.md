Setup & Testing — stripe-webhook Edge Function

This document collects step-by-step instructions to finish the remaining setup: environment variables, Supabase secrets, Stripe webhook configuration, SendGrid setup, and local testing.

1) Database
- Run the SQL below in the Supabase SQL editor (or psql) to create the `orders` table used by the function and the Next app.

```sql
CREATE TABLE public.orders (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  order_id text NOT NULL,
  customer_name text NOT NULL,
  customer_email text NOT NULL,
  phone_number text,
  delivery_address text,
  product_name text NOT NULL,
  product_handle text,
  shoe_size text,
  amount_minor int4 NOT NULL,
  currency text NOT NULL,
  order_status text NOT NULL DEFAULT 'pending',
  payment_status text NOT NULL DEFAULT 'pending',
  stripe_checkout_session_id text,
  stripe_payment_intent_id text,
  paid_at timestamptz,
  payload jsonb,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);
CREATE UNIQUE INDEX ON public.orders (order_id);
```

2) Environment variables (what each does)
- `SUPABASE_URL`: your Supabase project URL (e.g. https://abcxyz.supabase.co)
- `SUPABASE_SERVICE_ROLE_KEY`: Supabase service role key (full DB access) — keep secret
- `SUPABASE_ORDERS_TABLE`: optional (defaults to `orders`)
- `STRIPE_WEBHOOK_SECRET`: signing secret provided by Stripe for the webhook endpoint
- `SENDGRID_API_KEY`: SendGrid API key used to send transactional emails from the Edge Function
- `ADMIN_EMAIL`: recipient for admin notifications
- `SITE_URL` or `NEXT_PUBLIC_SITE_URL`: site origin used for links and email from address fallback

Where to set them
- For Supabase Edge Function runtime: set as Supabase secrets. Example (requires Supabase CLI / logged in):

```bash
supabase secrets set SUPABASE_URL="https://..." SUPABASE_SERVICE_ROLE_KEY="..." STRIPE_WEBHOOK_SECRET="..." SENDGRID_API_KEY="..." ADMIN_EMAIL="you@example.com" --project-ref your-project-ref
```

- For your Next.js app deployment (if you keep webhook in Next or use the order-service): set env vars in the hosting platform (Vercel/Netlify) or in `.env.local` for local development. Never commit `.env.local` with private keys.

3) Deploying the function
- Install Supabase CLI and login: https://supabase.com/docs/guides/cli
- From repo root run:

```bash
supabase functions deploy stripe-webhook --project-ref your-project-ref
```

- After successful deploy, the CLI output or dashboard will show the function URL.

4) Configure Stripe webhook
- In Stripe Dashboard → Developers → Webhooks → Add endpoint
  - Endpoint URL: `https://<project>.functions.supabase.co/stripe-webhook`
  - Events: `checkout.session.completed` (recommended) and optionally `payment_intent.succeeded`
- After creating the endpoint, copy the signing secret (looks like `whsec_...`) and set it as `STRIPE_WEBHOOK_SECRET` in Supabase secrets.

5) SendGrid setup
- Create a SendGrid account and generate an API key with `Mail Send` permission.
- Set `SENDGRID_API_KEY` as a Supabase secret.
- Ensure the `from` domain is verified in SendGrid (or use the `ADMIN_EMAIL` address you control).

6) Local testing options
- Option A — Test the deployed function directly from Stripe Dashboard using "Send test webhook".

- Option B — Use Stripe CLI to forward events to your local function while serving it:

  1. Serve the function locally (requires Supabase CLI):

  ```bash
  cd supabase/functions/stripe-webhook
  supabase functions serve stripe-webhook
  # by default it serves on http://127.0.0.1:54321/stripe-webhook
  ```

  2. In another terminal, install and run Stripe CLI and forward events to local endpoint:

  ```bash
  stripe listen --forward-to http://127.0.0.1:54321/stripe-webhook
  # then in a separate terminal trigger a sample event
  stripe trigger checkout.session.completed
  ```

- Option C — Use `ngrok` or `cloudflared` to expose local Next.js server at `http://localhost:3000/api/stripe/webhook` and configure that URL in Stripe's Webhook settings for manual testing.

7) Verifying behavior
- After a successful `checkout.session.completed` webhook, check:
  - Supabase `orders` row for the `order_id` has been updated to `payment_status = 'paid'` and `paid_at` populated.
  - SendGrid dashboard (or email inbox) for the customer and admin emails.

8) Notes & troubleshooting
- If the Edge Function logs show `Invalid signature`, confirm the `STRIPE_WEBHOOK_SECRET` matches the webhook endpoint (not the secret key). If using the Stripe CLI `listen` command, it prints a different signing secret — use that when testing locally.
- If emails are not sending, check SendGrid API key permissions and verified sender domains.
- The function uses the Supabase service role key to update rows. If you want stricter control, consider making a dedicated DB role and stored-procedure to do the update instead.
